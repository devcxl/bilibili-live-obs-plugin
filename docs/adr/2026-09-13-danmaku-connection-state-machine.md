# ADR-006: 弹幕连接状态机与自动重连策略

## 状态

已接受 (Accepted) — 2026-09-13

取代 [ADR-005](2026-09-13-danmaku-no-auto-reconnect.md)（该 ADR 完全移除自动重连，导致网络抖动后弹幕永久中断）。本 ADR 恢复 [ADR-002](2026-07-25-danmaku-websocket.md) 决定 4 的指数退避重连，并补充区分「网络抖动」与「用户主动关闭」的语义。

---

## 背景与问题

[ADR-005](2026-09-13-danmaku-no-auto-reconnect.md) 移除了全部自动重连，副作用是：长直播中任何一次网络抖动都会导致弹幕永久中断，用户必须手动点按钮才能恢复，体验与「实时弹幕展示」的产品目标冲突。

需要区分两类断开：

| 断开来源 | 期望行为 |
|----------|----------|
| 网络抖动、对端关闭、握手/鉴权失败 | 自动重连，尽量恢复到正常接收状态 |
| 用户主动关闭弹幕互动 | 彻底停止，不再自动重连 |

## 决策

### 决策 1：显式连接状态机（Closed / Connecting / Connected）

`DanmakuWebSocket` 对外暴露三态，取代原先的多个布尔标志（`authenticated_` / `is_connecting_`）：

| 状态 | 语义 | UI 表现 |
|------|------|---------|
| `Closed` | 未建立连接且无重连计划 | 文案「已关闭」，按钮「连接」，可点击 |
| `Connecting` | 握手/鉴权中，或处于重连退避等待 | 文案「连接中...」，按钮「连接中」，置灰不可点 |
| `Connected` | 鉴权成功，正常接收弹幕 | 文案「已连接」，按钮「关闭」，可点击 |

状态通过 `connection_state_changed(State, popularity)` 信号通知 UI，**状态未变化时不重复发信号**，避免退避期间 UI 反复闪烁。

### 决策 2：用户意图由 `session_active_` 单一标志表达

- `connect_to_room()` 置 `session_active_ = true`（进入互动）。
- `disconnect_from_room()` 置 `session_active_ = false`（退出互动），并停止重连定时器。

所有自动重连路径先检查该标志，因此「手动关闭后不再重连」是一条硬约束，不受后续任何断开事件影响。

### 决策 3：指数退避重连（2s → 4s → 8s → 16s → 30s 封顶）

- 退避在 `start_app` 失败、未返回 `wss_link`、WSS 断开时触发。
- `7001`（官方冷却期）起点放大到 5 秒，避免自我放大限流。
- 鉴权成功后 `reconnect_attempts_` 归零，长时间稳定连接后的偶发抖动可快速恢复。
- 「参数不完整」属配置错误，重试无意义，直接回到 `Closed` 且清空 `session_active_`。

### 决策 4：连接尝试生命周期用 `attempt_in_flight_` 精确追踪

`attempt_reconnect()` 仅在「无进行中的连接尝试且未处于 Connected」时发起新一轮，避免重连定时器与在途请求竞争、重复调用 `start_app` 触发 7001。

## 替代方案及排除理由

| 方案 | 排除理由 |
|------|----------|
| 完全不自动重连（ADR-005 原方案） | 网络抖动导致弹幕永久中断，与实时弹幕的产品目标冲突 |
| 固定间隔重连 | 高频重连可能触发官方风控与 7001 冷却期 |
| 自动重连但状态仅用布尔量表示 | 无法区分「连接中」与「已关闭」，按钮无法正确置灰，用户可能重复触发 `start_app` |
| 重连期间隐藏面板 | 用户失去弹幕历史，且无法观察正在恢复的过程 |

## 后果与影响

**正面**

- 网络抖动可自愈，长直播中弹幕可用性显著提升。
- 用户意图明确：点「关闭」即彻底停止，不会出现「后台偷偷重连」。
- UI 与真实状态严格一致（三态一一对应文案、按钮文字与可用性）。
- 状态机取代多个布尔标志，消除了「`authenticated_` 与 `is_connecting_` 组合状态不明确」的问题。

**负面与缓解**

| 影响 | 缓解 |
|------|------|
| 持续故障时退避最长 30s 一次，期间按钮置灰无法手动打断 | 退避期间仍可等待下一轮；如需强行打断可关闭弹幕互动（`Closed` 后按钮恢复可点） |
| 长时间无弹幕时用户可能不知已在重连 | 状态栏实时显示「连接中...」 |
| UI 不再显示「正在重连（第 N 次）」 | 重试次数记录在 OBS 日志中；如需可视提示可后续暴露到状态文案 |

**回滚边界**

改动集中在 `DanmakuWebSocket` 状态机与 `DanmakuDisplay` 的三态渲染，回滚只需恢复 `connection_state_changed(bool, int)` 签名与相关调用点，不影响协议编解码、消息解析、TTS 与推流链路。
